# Domain Docs

本项目采用单一业务上下文。

## 读取规则

- 开始业务设计或代码探索前，读取根目录 `CONTEXT.md`。
- 读取 `docs/adr/` 中与当前工作有关的架构决策。
- 文档不存在时继续工作；不为了补齐目录而预先创建词汇表或 ADR。

## 文档职责

- `CONTEXT.md` 是业务词汇表；使用其中的规范术语，不加入实现细节或把它改成需求规格。
- `SPEC.md` 描述本 Demo 的业务行为、技术方案和验收要求。
- `docs/adr/` 按需记录难以逆转、需要解释真实取舍的架构决策；不为常规实现选择创建 ADR。

Issue、规格、测试名称和代码讨论使用词汇表中的业务语言。发现重要业务术语缺失时，通过 domain-modeling 记录定义。

与已有 ADR 冲突时明确指出冲突及原因，不静默覆盖原决策。
